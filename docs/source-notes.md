## Suggested provisional glossary

| Term | Working definition | Status |
| --- | --- | --- |
| Scenario | A specific trigger-to-outcome journey worth understanding or improving. | Shared direction; one-to-one pairing is a proposed convention. |
| Trigger | The event or condition that starts the scenario. | Working definition. |
| Outcome | The result the scenario should achieve, with a success measure when known. | Working definition. |
| Component | A person, team, tool, system, or agent that participates in the route. | Broad category consistent with the calls. |
| Signal | Information or an event passed between participants or components. | Working definition; do not equate every connection with verified live data. |
| Handoff | A transfer of information, responsibility, or work between steps. | Useful implementation vocabulary, synthesized from the discussion. |
| Surface | A place or context where someone or something can interact with the system. | Explicitly unresolved in the latest call. |
| Channel | A communication medium, such as phone or email. | Possible narrower meaning; not final. |
| Friction | A delay, missing context, unnecessary step, uncertain responsibility, or other obstacle to the outcome. | Useful synthesis for MVP mapping. |
| Future state | The way the scenario should operate if the desired change succeeds. | Central direction across both calls. |

## Recommended minimum prototype loop

1. Choose a seeded fictional scenario or start a blank one.
2. Capture the scenario, trigger, desired outcome, and workshop notes.
3. Create, edit, order, and connect a small number of route steps/components.
4. Inspect each step's people/tools, information passed, and friction; mark evidence or assumptions.
5. Record a future-state hypothesis and one next experiment, including owner and success evidence.
6. Save locally and export a portable workshop artifact for Ben and Paul to exchange.
