# Workshop the same pattern in different businesses

## Start with a case

Open an industry example, or **Define a flow**. Name the business object and identity field, the trigger, and the intended outcome with evidence. A booking disruption, referral request, and order exception use the same model.

The examples are fictional administrative workflows. They demonstrate a vocabulary, not industry-certified procedures.

## Map the work

Add actions and connect them with signals. For each action, separate the business capability from the component performing it. Capture required input keys, produced context, case state, owner/component, surface/channel, friction, and source evidence.

Decisions need explicit alternative routes. This prototype supports context-ready/incomplete and exception/standard conditions. It checks those routes for coverage and exclusivity. Capture more complex real-world policies in the notes until the model supports them.

Click an action for its contract. Use **Capabilities** to see how business abilities are implemented by different components. A terminal outcome can be met, pending, or not met; reaching a waiting state does not mean success.

## Propose a better operating flow

Open **Proposed flow** to create a separate copy. Edit its actions, signals, and delegation contracts without changing the current flow.

For an AI candidate, define a bounded task, required inputs, expected output and acceptance check, review requirement, fallback owner, and proposed handling time including review. Start with context assembly, extraction, and draft preparation. Keep acceptance/authorization explicit before commitment.

The flow brief also holds the desired future state, first move, success measure, accountable owner, fallback, and open questions.

## Rehearse the case

Test normal conditions, missing context, exceptions, uncertainty, and tool failure. Use the same inputs for current/proposed comparison. Confirm simulated review or reject a proposal; observe whether downstream signals are emitted.

All outputs and timings are rehearsal assumptions. Test against real case evidence before treating a proposed flow as an operational improvement.

## Work with AI

Use **AI designer** to export a schema-based brief for your AI tool, then validate its JSON proposal. Or configure the [local AI connection](ai-connection.md). Applying a model draft replaces only the proposed flow and preserves the current one.

## Keep the learning

Export the complete workspace for another device; export a flow brief or rehearsal trace for discussion. Open **Company notebook** and record what the workshop changes about your mission, vocabulary, customer, or business model.

Ask: which terms stayed useful across industries, what depended on local policy, where did context disappear, and which specific action was worth delegating?
